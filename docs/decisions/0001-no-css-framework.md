# 0001. Plain CSS, no CSS framework

- Status: accepted
- Date: 2026-10-18

## Context

The library must work in any site: static HTML, a CMS theme (Drupal first), or a JavaScript application. It replaces a commercial template whose markup was tied to a specific framework and build. Utility-first frameworks and component frameworks would each force a build tool, a class vocabulary or a runtime on every consumer.

Modern CSS now covers what frameworks used to provide: custom properties, cascade layers, container queries, `:has()`, logical properties, `clamp()` and native nesting.

## Decision

Write the library in plain CSS with BEM-style class names (`oo-block__element--modifier`), organised into cascade layers: `oo.reset`, `oo.tokens`, `oo.base`, `oo.components`, `oo.patterns`. No preprocessor and no utility framework. Vite is used only to bundle `@import` statements and produce `dist/`.

Patterns size themselves with container queries where it makes sense, so they adapt to the box they are placed in rather than the viewport.

## Consequences

- Consumers get readable CSS they can inspect and override without learning a framework.
- Cascade layers mean any unlayered site CSS wins, so overrides need no `!important` and no specificity tricks.
- Some repetition (for example the dark theme block) cannot be generated by a preprocessor; tests guard it instead.
- Browser support is limited to browsers with cascade layers, container queries and `:has()` (roughly 2023 onward). This is acceptable for personal and portfolio sites.
